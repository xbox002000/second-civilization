# 第二次文明｜Second Civilization

**AI 驅動的時事敘事與長篇小說 IP 工作流**

> 核心命題：當 AI 工具逐漸普及，真正拉開差距的，不只是模型能力，而是人如何定義問題、理解系統、驗證判斷並採取行動。

## 專案目標

把《第二次文明》建立成一個可長期運作的內容 IP：吸收真實世界事件，完成來源查核與系統分析，再轉化為符合人物與世界觀的劇情，最後產出長篇小說、短影音、圖文與社群內容。

第一階段只建立可執行、可驗收的工作流。先用人工／半自動方式跑通一集，再決定哪些步驟值得自動化。

## 故事基本設定（已確認）

- 主角歷史身份：范蠡（以歷史人物為原型，內心與轉世經歷屬小說創作）。
- 穿越方式：轉世／reincarnation。
- 現代年齡：年輕。
- 終極追求：真相。
- 核心思想：人人都能使用 AI，但不同的認知結構會帶來不同的使用結果。

未確認的細節（現代姓名、確切年齡、出生背景、記憶甦醒方式、配角名單）不得被 Agent 自動當成正式設定；需經創作者確認後寫入角色聖經。

## 核心工作流

事件收件 → 情報研究 → 事實查核 → 系統／利益結構分析 → 世界觀適配 → 劇情提案 → 編劇 → 獨立審稿 → 人工核准 → 內容轉製 → 發布 → 數據回饋。

## 工具邊界

- **GitHub**：正式規格、Agent 指令、模板、Schema、程式與版本控制。
- **AFFiNE**：視覺化世界觀、角色、事件與劇情知識庫。
- **Paperclip**：任務派發、狀態管理、Agent 執行與交接。
- **AI Agents**：依照本倉庫的規格完成具體交付物。

GitHub 是版本來源；AFFiNE 不取代正式規格；Paperclip 不取代內容審核。

## 第一個 MVP

輸入一則有來源的真實事件，產生一份可追溯的內容包：
1. 事件研究卡（來源、發布時間、擷取時間、資料截止時間）。
2. FACT / INFERENCE / HYPOTHESIS / FICTION 分層。
3. 利益結構分析、替代解釋、反證條件與未知數。
4. 范蠡視角與 AI 反方觀點。
5. 符合角色設定的劇情提案。
6. 一份短影音或圖文草稿。
7. 審稿結果與人工核准紀錄。

## 專案目錄

- `docs/`：專案規格、流程與決策紀錄。

- `schemas/`：結構化資料契約。
- `examples/`：可重複測試的示例資料。

## 開發原則

1. 先可驗證，再自動化；先小流程，再擴張。
2. 每個 Agent 必須有明確輸入、輸出、驗收條件和失敗回報。
3. 不得把推論、假設或虛構包裝成事實。
4. 時事分析必須保存時間戳，防止事後資訊冒充事前判斷。
5. 主角與 AI 都必須允許犯錯、被反駁與修正。
6. 對外發布、重大金融／政治主張與敏感內容必須經人工審核。
7. 不為架構完整而先增加昂貴服務或複雜技術。

# 工作流規格 v0.1

## A. 一集內容的端到端流程
```text
事件／題目收件
  ↓
情報研究與來源蒐集
  ↓
事實查核與時間線固定
  ↓
系統分析（參與者、利益、資源、權力、依賴）
  ↓
世界觀與角色適配
  ↓
劇情提案（衝突、選擇、代價、懸念）
  ↓
編劇與格式化
  ↓
獨立審稿
  ↓
人工核准
  ↓
影音／圖文製作與發布
  ↓
數據回收、復盤與知識庫更新
```

## B. 階段定義與退出條件
| 階段 | 負責角色 | 工作 | 退出條件 |
|---|---|---|---|
| S0 收件 | Producer | 建立事件／題目 ID、判斷初步相關性 | 有唯一 ID、問題、原始線索與收件時間 |
| S1 研究 | Researcher | 找原始來源、整理時間線和主張 | 關鍵主張有來源；缺口已列出 |
| S2 查核 | Fact Checker | 獨立驗證來源、數字、引用、時間 | 主張逐項標記；未證實處明確揭露 |
| S3 分析 | Systems Analyst | 拆解利益結構與可能情境 | 有反方解釋、脆弱假設、未知數與反證指標 |
| S4 世界觀適配 | World Keeper | 檢查角色、記憶、時間線與故事主線 | 不與 Canon 衝突；必要變更提出申請 |
| S5 劇情提案 | Writer | 將真實事件轉為人物衝突 | 事實與虛構分明；衝突源於人物目標 |
| S6 編劇 | Writer | 按媒體規格寫稿 | 初稿完成、來源可追溯、節奏符合格式 |
| S7 審稿 | Reviewer | 獨立檢查事實、推理、人物、版權和風險 | PASS，或列出明確返工項目 |
| S8 人工核准 | Creator / Producer | 決定製作及發布 | 核准者、版本、時間與範圍已記錄 |
| S9 發行 | Format Producer | 分鏡、配音、剪輯、排程、發布 | 發布位置、時間、素材版本入庫 |
| S10 復盤 | Performance Analyst | 分析表現與觀眾反應 | 形成可驗證的下一輪改進假設 |

## C. 狀態機
`INBOX → RESEARCHING → FACT_CHECK → ANALYZING → CONTINUITY_CHECK → STORY_PROPOSAL → DRAFTING → REVIEW → HUMAN_APPROVAL → PRODUCTION → PUBLISHED → RETROSPECTIVE`

退回狀態：`NEEDS_SOURCES`、`NEEDS_FACT_CHECK`、`NEEDS_ANALYSIS`、`NEEDS_CONTINUITY_FIX`、`NEEDS_REVISION`、`REJECTED`。

每次狀態變更都要記錄時間、操作者、原因、版本與下一個負責人。不得跳過人工核准直接發布。

## D. 事件優先級
候選事件以 1–5 分評估：受眾相關性、現實影響程度、證據品質、認知分析深度、劇情衝突潛力、時效性。

總分用於排序，不代表事件為真或必須製作。證據品質低於 3 分時，不進入以事實報導為包裝的正式劇情；可以改成明確標示的觀點／假設內容。

## E. 發布閘門
下列內容必須人工審核：金融、政治、公共安全、個人名譽、重大指控、未證實預測、涉及真實人物的虛構描寫，以及任何對外發布或付費投放。

## F. MVP 驗收
用一則事件從 S0 跑到 S7，交付一份研究卡、一份查核報告、一份系統分析、一份劇情提案、一份短影音腳本與一份審稿報告。全流程先人工／半自動運行，記錄時間、返工率、資料缺口，再選擇自動化位置。

# Decision Lab｜范蠡決策壓力測試

> 目的：將 Persona Bible 從「人物描述」轉成「可被反駁、可回歸測試的決策行為」。
>
> 本資料庫不是投資建議、企業評級或歷史人物心理鑑定。真實事件提供事實底座；角色回答與對手反駁均屬小說創作模擬。

## 為什麼要有 Decision Lab

一個角色不能只靠人格形容詞成立。「冷靜、善觀勢、懂進退」很容易被模型寫成每次都正確的萬能顧問。

Decision Lab 要測試的是：當資訊不完整、時間有限、利益衝突，甚至范蠡自己的假設錯誤時，他會如何思考、如何選擇、如何承擔代價。

## 每個案例的固定流程

1. **Freeze the clock**：先固定決策時點，寫明當時可取得的資訊。
2. **Fact ledger**：分開 FACT、INFERENCE、HYPOTHESIS、UNKNOWN。
3. **Fan Li first pass**：范蠡在尚未看到反方觀點前先作判斷。
4. **AI red team**：AI 找出隱含假設、反例、反向因果與可能錯誤。
5. **Domain expert**：以該領域專家角度指出角色不懂或忽略的專業問題。
6. **Reviewer**：檢查來源、推理、人格、倫理與時間線。
7. **Revision**：范蠡回應反駁，決定維持、修正或暫停原判斷。
8. **After-action**：只有在有後續事實時才做事後檢討，不能倒灌進初始判斷。

## 時間封存規則

- 初始決策只可使用案例的「決策時點」以前已公開、可合理取得的資訊。
- 後來才確認的調查結果、判決、營運數據，放在「事後稽核」，不可假裝角色當時已知道。
- 公司自行公布的數字要標為「公司披露」；政府或法院的認定要標明機關與日期；媒體報導不得改寫成已證實的內部事實。
- 預測必須寫出時間範圍、成功指標、反證條件及退出條件。
- 資料來源有爭議時，保留多個版本，不強行合併。

## 評分規則

每項 0–2 分，共 12 分：

| 維度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 事實紀律 | 把傳聞當事實 | 有區分但不完整 | 明確標示事實、推論與未知 |
| 系統理解 | 單因解釋 | 看到部分因素 | 能辨識參與者、依賴、瓶頸與回饋 |
| 時機判斷 | 躁進或無限拖延 | 有條件但不清楚 | 清楚設定等待、行動與重評估窗口 |
| 可逆性與風險 | 忽略下行風險 | 有提及風險 | 有分階段、止損、退出或保護措施 |
| 接受反駁 | 防衛或盲從 | 有回應但含糊 | 能指出哪些反駁成立、哪些仍待證 |
| 人性與倫理 | 把人只當工具 | 有提到倫理 | 看見承擔者、權力不對稱與補救責任 |

分數不是「預測準確率」。它只衡量角色是否符合規格。決策結果要另以事後資料檢驗，不能以結果倒推當時推理必然正確。

## 角色分工

- Researcher：建立時間線、收集來源與資料截止時間。
- Fact-checker：核對關鍵數字、來源屬性與錯誤歸因。
- Systems Analyst：拆解利益、依賴、瓶頸與替代方案。
- 范蠡模擬：先提出自己的判斷，不先看 AI red-team。
- AI Red Team：提出最強反方論證，不為范蠡找台階。
- Domain Expert：指出專業知識盲區。
- Reviewer：獨立評分；必要時 REVISE / REJECT。
- World Keeper：把經測試且由創作者接受的人物特徵回寫 Canon；不得自動升格。

## 第一輪驗收標準

- 六個案例皆有來源、決策時點、未知數與反證條件。
- 至少一個案例完整跑完「初判 → 反駁 → 修正 → 評分」。
- 不以單次高分宣稱人格已定型。
- 找出至少三種角色盲點，回寫 Persona Bible 或 Voice Guide。
- 完成後才考慮自動化，不先做微調或 LoRA。

## 一、對覆盤三條結構性結論的裁決

### 結論 1：「身份沒有『資產』、只有『參考』」→ **REFINED（同意痛點，修正技術定位與成因）** `[與 Muse 覆盤分歧]`

- **同意處**：在長距離轉頭或推近時，僅靠單張首幀 `i2v` 無法保住角色骨相、年齡與服裝細節（`demo02/qc/sheet_S3a_v2.jpg` 為鐵證：同一支片 `f_0` 是 38 歲范蠡，`f_mid` 轉頭拉近即變成 22 歲陌生青年且衣領翻成左衽）。高風險特寫／對白鏡必須引入多參考載體。
- **修正與反駁處**：
  1. **多參考 Ref2VA／RefMod 皆非確定性「硬鎖」，只是較強的條件錨**：依 `H3_CONSISTENCY_CAMERA_AGY_MEMO.md` §三 Q1 查證，RefMod 是免訓練的 3D VAE 參考潛空間包（`.safetensors`），仍經 `CONDITIONING` 注入，並非 3D 綁骨資產；若把它當成「裝上就能省 QC 的硬鎖」，只會製造下一代盲區。依減法紀律，優先以閘道免安裝的 **原生 4 槽 H3 Ref2VA（SM-7A）** 為主力基線，**RefMod 維持 WATCH（SM-7B）**。
  2. **S3a 漂移的結構性共犯是「首幀人臉尺幅不足卻硬做推臉／轉頭」**：`S3a2` 首幀為偏遠中景，卻在 `video_prompt` 要求「瞳孔收縮＋轉頭」，強迫單首幀 i2v 放大低解析人臉並無中生有。
  3. **資產銀行本身存在方向盲區**：`casting/master/` 的 `FANLI-OUTFIT-02` 僅有正面與左側 45°（皆露出左眉疤），**缺右側 45°（無疤側）與大特寫臉部基準**，導致 S4 面朝右側時，i2i 直接把左眉疤錯貼到右眉。
- **修訂後結論**：工作流需要「**按鏡型強制分流的身份載體（多圖 Ref2VA vs 同源衍生同尺幅 i2v）＋ 補齊右側無疤基準圖 ＋ 禁止單首幀 i2v 跨尺幅大幅推臉**」，三者缺一不可。

### 結論 2：「QC 驗的是便宜的物件（首幀），不是交付的物件（成片）」→ **REFINED / PARTIALLY REBUTTED（同意補齊成片驗收，但反對降格首幀 QC）** `[與 Muse 覆盤分歧]`

- **同意處**：凡動態生成階段會衰減或漂移的屬性（跨幀年齡穩定、傷痕持續在位、青光保持度、口型與微動作），絕不能「首幀過就當成片過」，必須在進入組裝與 QC-D 前完成成片抽幀驗收。
- **反駁處**：
  1. **反對「首幀 QC 只管構圖與身分近似」**：實勘證實 S4 傷痕跑錯邊、S3b 左衽反領與缺木笄／缺玉璧、S2 缺冠缺笄、S2R 婦人移位與菜籃憑空出現，**100% 在 QC-1 首幀階段就已存在**。若把 QC-1 降格為「只看近似」，只會把必退的首幀送進 Veo／H3 白燒點數與 Colab CU。
  2. **成片早有抽幀，漏網是因為「缺錨點對照＋缺硬閘」**：`demo02/qc/` 已產出各鏡 3 幀聯絡條與 `sheet_final.jpg`，但沒把 Master 臉／服裝卡／首幀貼在同一列並做 2.5× 臉領放大，又沒擋住 `assemble.sh`，導致人工快掃全數漏接。
- **修訂後結論**：採**雙門對稱防線（Dual-Gate Symmetry）**——**QC-1（首幀門）硬鎖靜態不變量**（解剖傷痕側、服裝四項、段光強度、姿勢接點與同景連戲），**QC-2（挑片門）硬鎖動態保持率與跨鏡對齊**（定裝＋首幀＋成片抽幀並排 diff 表），兩門都以簽核 JSON 檔阻斷下游執行，讓 QC-D 專心審導演六檢。

### 結論 3：「Demo 模式是隱形降級」→ **STRONGLY AGREE + ESCALATE（完全同意並補齊真正根因）**

- **同意處**：DEMO-01 跳過段光線繼承、DEMO-02 跳過路由鎖與比對 QC——兩次翻車都不是規格漏寫，而是「只是試水」的心態把規格掏空，反過來汙染對工作流能力的判斷。
- **追查深層根因 `[與 Muse 覆盤補充]`**：DEMO-02 不只繞過路由，而是**直接棄用 `script_pack.json` 與 prompt 衍生公式**，改由手寫 `demo02/gen_clips.sh` 注入中文裸否定句（`男子貼牆不動`、`兩人都不說話，動作克制`、`緩緩開口低聲說話` 缺台詞本文）。只要工作流允許「demo 可以不寫 `script_pack.json` 直接敲工具命令」，未來每一次試拍都會重演隱形降級。
- **修訂後結論**：**Demo 模式不得是「另一條手敲捷徑」，而必須是同一條管線上的 `--mode demo` 參數**——只准縮減「產量（鏡數／抽數）與精修封裝（Stage 6B/7）」，嚴禁繞過 `script_pack.json`、前置驗證閘、身份載體、跨鏡比對 QC 與路由鎖。

## 六、同場景衍生規則（Same-Location Derivation Rule）

> **核心原則**：在同一 `segment_id`（共用同一個 `scene_id`）內，**只有第 1 顆建立鏡（Anchor Shot）可單獨由空景母圖＋角色定妝生成**。其後所有同場景鏡頭（反打、過肩、切近、人物續動）一律按下列三條合法路徑生成，禁止「把空景板拿來從頭用文字重編一次」。

| 路徑 | `first_frame.source` 值 | 適用場景 | 合法輸入組合（嚴守 V3 順序） | 解決的失敗模式 |
| :--- | :--- | :--- | :--- | :--- |
| **Path A：核准錨鏡同源衍生**（預設主力） | `derived_shot`（必填 `ref_shot_id`） | 同軸切近（MS→MCU→CU）、同景人物續動、雙人鏡拆單鏡、同側目擊者短反打（如 DEMO-02 `S2 → S2R`、`S2 → S3a → S3b → S4`） | `[已核准錨鏡首幀或成片末幀 (ref_shot_id), 目標角色身分/服裝卡]` 送免費 `gflow nano2 i2i`；prompt 明示「維持 `<Ref 1>` 既有站位、服裝與背景物件，僅將機位推近／偏移至目標景別與角度」 | **直接消滅 `S2R` 婦人換邊＋菜籃憑空出現**，並天然鎖住同段光線、巷壁管線與機車位置 |
| **Path B：雙鎖反打（反打空景＋錨鏡雙錨）** | `generated_dual_lock`（必填 `scene_angle_id` ＋ `ref_shot_id`） | **真 180° 正反打**（鏡頭轉向錨鏡看不見的對面牆壁／巷口方向，無法單靠錨鏡畫面延伸） | **前置**：階段 1 先以主空景 `LOC-ID.jpg` 生成並鎖定成對的 `LOC-ID_rev.jpg`（同天色、同濕地反光、登錄 `assets_manifest.yaml`）。<br>**首幀生成**：嚴格三槽餵 `[LOC-ID_rev (對向背景), 已核准錨鏡 (鎖人物衣著／手提袋／軸線), 角色基準卡]` | 兼顧對向真實空間結構與已出場配角（如婦人米色短外套＋紅白塑膠袋）外觀不飄 |
| **Path C：CozyClay 共用場地白膜匯出**（選配，受 V11 每集 ≤2 鏡限） | `l3_clay_frame0`（記於 `previs_artifacts`） | 需要跨多鏡嚴格 3D 幾何透視／前景遮擋／首尾呼應的英雄段（如 EP-01 `S01` 與 `S16b`） | 在同一 CozyClay 專案內擺妥雙機位，各匯出 `frame0` PNG 供 Stage 3 烘焙首幀 | 杜絕複雜空間機位穿幫與跨集首尾呼應走位偏差 |

### 明確違法路徑（`preflight_gate.py` 硬駁回）
1. **違法①**：同 `segment_id` 內第 2 鏡起，以 `first_frame.source = "generated"` 僅餵空景母圖 `LOC-*`＋純文字描述已出場人物或道具（即 DEMO-02 `S2R` 翻車路徑）。
2. **違法②**：未經 `continuity_override` 聲明即翻轉 180° 軸線（例：`S2` 范蠡在左、婦人在右，下一鏡無理由把婦人畫在左邊朝右看）。
3. **違法③**：在已出場鏡之後，未填 `ref_shot_id` 卻要求背景保留同一名臨演／目擊者。

### 7.1 生成端「乾淨人物底板（Actor Plate）」拍法規範
1. **構圖留白區（Landing Zone）**：以 `S3b`（MCU）為例，范蠡站位鎖在畫面**左側 45%**，右側預留乾淨暗部空間（1080×1920 座標 `x ∈ [520, 1020], y ∈ [360, 1280]`，完全避開 IG/Shorts 右側與底部 UI 區）給後製疊加彈窗。
2. **運鏡紀律（免 2D 平面追蹤關鍵）**：彈窗停留鏡（`S3b`）採 **`static` 鎖定機位**或純線性極緩推（`amplitude: small`），**生成端禁止劇烈不規則手持晃動**——如此 Phase 3 不需要任何光流追蹤器（Tracker），待彈窗與人物合成完畢後，再於最外層統一套用 `3%` 裁切＋微幅呼吸緩推／微晃（讓人物與 UI 共用同一相機運動，毫無浮貼感）。
3. **視線與演技**：首幀與 prompt 鎖定范蠡視線直盯畫面右側預定錨點（`x≈780, y≈760`），演出明確的 `startled turn → back against wall → tense breathing`；**prompt 嚴禁出現「全息屏幕／彈窗／女性頭像／文字」字眼**（V9 硬擋）。
4. **打光策略（乾淨底板＋後製精準回打）**：`S3a`（觸發前）與 `S3b`／`S4` 一律維持乾淨段光 `LK-ALLEY-NIGHT` 拍攝（不依賴 AI 憑運氣把青光留在 S4）；青光開關、閃爍節奏與跨鏡一致度 100% 交由後製 Layer 1 控制。

### 9.2 若全案「只允許做一項修訂」，我的單一選擇

**唯一選擇：`AMD-02 + AMD-03` 合併為單一硬閘——「自動產出高解析跨鏡 Diff 總表（含 2.5× 臉領放大）＋ 強制簽核 `qc1_gate.json` / `qc2_gate.json` 阻斷下游（Stage 4 與 Stage 6A）」**。

**選擇理由（逐一對照 DEMO-02 六類失敗）**：
1. **覆蓋面最廣（唯一能直接攔截 6/6 類失敗的單一修訂）**：
   - 若只改身份載體（`AMD-01`）：能救 `S3a` 變臉與 `S4` 口型，但**攔不住** `S4` 首幀右眉錯疤、`S3b` 左衽反領、`S2R` 婦人換邊生菜籃、`S1` 路燈爆光、`S2` 僵直不動、`S1→S2` 姿勢跳接。
   - 若只立 Demo 邊界條文（`AMD-06`）：沒有機器閘門的純條文，下次趕時間一樣會被心理合理化繞過。
   - 反觀「**腳本強制產出高解析跨鏡對照表（鎖死定裝錨＋首幀＋成片抽幀＋2.5× 臉領放大）＋ 無簽核 JSON 就物理拒絕跑 Stage 4 與 Stage 6A**」：
     - **4 類失敗在 QC-1 就地止損**（S4 錯邊疤、S3b 反領缺玉璧、S2 缺冠、S2R 婦人移位與菜籃、S1→S2 姿勢跳接），連 1 點 Veo 算力都不用浪費；
     - **其餘 2 類失敗在 QC-2 立即現形**（S3a 中段變 22 歲青年、S4 青光不足、S1 路燈爆白、S2 蠟像僵直、S3b 彈窗表情不搭），絕不會流進粗剪讓 QC-D 成為第一個踩雷的人。
2. **誠實揭露其單一局限**：此修訂本質是**「高信噪比防火牆」而非「生成能力升級」**——若不搭配 `AMD-01`（H3 多圖 Ref2VA）與 `AMD-07`（路由與方言編譯），它雖能 100% 擋下不合格品，但特寫對白鏡會陷入反覆重抽循環。因此在實務上，它應作為**最先鎖死的底線閘門**，並緊接搭配 `AMD-01`（SM-7A 驗證）與 `AMD-07` 一起落地，形成「上游做對＋兩站驗對」的完整閉環。

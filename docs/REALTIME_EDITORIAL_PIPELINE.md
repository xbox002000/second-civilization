# 即時時事與故事轉化流程 v0.1

## 1. 輸入來源

- 主流新聞與官方公告。
- 公司財報、研究論文、監管文件、法院文件與公共資料。
- X 等平台的公開討論與趨勢訊號（只作線索，不能直接當作事實）。
- 觀眾留言、提問、投票和提供的資料。
- 長期追蹤議題與先前公開推論。

每個事件先建立 Event ID，不以截圖或轉貼文作為唯一證據。

## 2. 即時選題閘門

Producer 對每個候選事件檢查：
1. **公共相關性：** 這件事對受眾的生活、工作、資源或制度有何影響？
2. **證據品質：** 是否找到原始來源？哪些關鍵主張仍未確認？
3. **時效窗口：** 現在發言是否仍有增量價值？有無必要等待更多資訊？
4. **范蠡視角：** 事件是否能透過利益、權力、資源、風險、時機或人性提供有辨識度的觀察？
5. **敘事潛力：** 有沒有選擇、衝突、關係和代價，而不只是熱度？
6. **風險：** 是否涉及正在進行的政治爭議、金融市場、公共安全、名譽指控或受害者隱私？

優先級是製作排序，不是事件真偽評分。資料不足時可發布「目前知道什麼／不知道什麼」，或暫不發言。

## 3. 固定製作流程

### S0 — Trend Intake
建立候選事件，記錄來源網址、發現時間、事件時間、熱度訊號和受眾問題。

### S1 — Research Dossier
Researcher 建立事件時間線、來源等級、重要主張、當事人說法、反方資料和未知數。

### S2 — Fact Check
Fact Checker 逐項驗證重要主張，記錄來源是否一手、是否獨立、資料截止時間和衝突。

### S3 — Systems Analysis
Systems Analyst 建立參與者地圖、利益／成本分配、資源與權力節點、依賴關係、替代解釋和反證指標。

### S4 — Fan Li First View
范蠡 Persona Agent 在尚未讀到 Red Team 結論前，先產生：
- 一句核心觀察。
- 一個最容易被忽略的前提。
- 一項暫時判斷。
- 兩個未知數。
- 可能改變判斷的條件。
- 他個人可能犯的錯。

### S5 — Red Team & Domain Challenge
Red Team 找最強反方；有需要時由專業 Agent 或人類專家檢視。不得以反方只是「唱反調」；必須指出證據或因果缺口。

### S6 — Editorial Split
Producer 決定各內容線：
- 公開觀局／推演。
- 時事映照短篇。
- 主線提案（可選）。
- 短劇（可選）。
- 觀眾問答題目（可選）。

### S7 — Format & Review
各格式獨立審稿。時事評論查事實與表述；虛構故事查改編邊界、人物合成、Canon 與授權；短劇另查視聽可執行性。

### S8 — Human Approval & Publish
對外發布必須由 Creator 或授權人核准。高風險內容不能因為趕時效而略過審查。

### S9 — Audience & Event Follow-up
收集留言、反證、新資料、平台指標和事件後續；重要更正要連回原文並記錄，不靜默覆蓋舊判斷。

## 4. 時效分層

- **快訊層：** 先說已確認事實和未知數；不為搶快補猜。
- **分析層：** 待來源和主要利益結構較清楚後，提出角色判斷。
- **故事層：** 當抽象命題和人物衝突成熟，再生成短篇或短劇。
- **追蹤層：** 事件發展後回頭驗證先前推論。

並非每個事件都適合即時故事。快訊不等於短劇，故事更不能在事實尚未查清時替未證實指控加上情節。

## 5. 公開推論紀錄

每一個可驗證的重要推論都要存入 Prediction Ledger：
- prediction_id、content_id、建立時間、期限。
- 初始資訊集與資料截止時間。
- 觀察指標、成功／失敗定義。
- 核心假設、信心水準、反證條件。
- 結果、評估日期與角色事後反思。

不得刪除失敗預測來維持角色形象。可補充新資料，但原始預測需保留。

## 6. 發布閘門

任何對外內容均需人工核准。涉及政治、選舉、金融投資、法律、醫療、公共安全、名譽指控、未成年人或真實受害者時，提高證據與審查要求；必要時不做角色化推論或虛構改編。

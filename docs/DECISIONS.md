# 架構決策紀錄（ADR）

## ADR-001：獨立專案倉庫
- 狀態：ACCEPTED
- 決策：第二次文明使用獨立 GitHub repository，不放入 `My-AI-Novels`。
- 原因：`My-AI-Novels` 原本保存《臥龍豆包》小說稿，避免不同 IP 的 Canon、素材與工作流程混雜。

## ADR-002：先建立工作流，再開發自動化
- 狀態：ACCEPTED
- 決策：先用 Markdown 規格、模板和人工／半自動流程跑通一集，再開發整合程式。
- 原因：先驗證真正需要自動化的環節，避免先做出複雜但無法交付內容的系統。

## ADR-003：GitHub / AFFiNE / Paperclip 分工
- 狀態：PROPOSED
- 決策：GitHub 保存正式規格與版本；AFFiNE 用於視覺化知識庫；Paperclip 負責 Agent 任務編排。
- 待驗證：AFFiNE 與 Paperclip 的實際資料同步方式、可用 MCP 工具與權限。

## ADR-004：人工發布閘門
- 狀態：ACCEPTED
- 決策：MVP 階段所有對外發布皆需人工核准。

## ADR-005：范蠡身分基準採 Creator 本人臉版
- 狀態：ACCEPTED（2026-11-27 Creator 拍板）
- 決策：主角身分 master 以 Creator 本人照片生成的臉為準（讀感約 38–40 歲）；滄桑版與其他候選降為存檔。傷痕規格恆為左眉尾；master 圖本身為鏡像（疤在右），生成時必須改回左側。
- 原因：辨識度與「活人感」優先；本人臉版現代感與代入感最強。一致性全套（45°／背影／年齡變體）已生成並 QC 通過後鎖定。

## ADR-006：聲線定版與對白全面 TTS 化
- 狀態：ACCEPTED（2026-11-27）
- 決策：范蠡聲線鎖定 ElevenLabs Voice Design F・胸腔共鳴（eleven_v4、stability 0.65，參數見 bible/voices/FANLI.yaml）；全劇對白以 TTS 合成，生成引擎原生音訊只保留環境聲／音效。
- 原因：第一輪 A–D 試聽全數否決（不夠低沉內斂），第二輪 F 通過驗收；TTS 化使對白可控、可重錄、不受生成引擎口型音質限制。

## ADR-007：短劇通路採完全獨立新帳號
- 狀態：ACCEPTED（2026-11-27）
- 決策：短劇不掛 @chao.and.nao（定調失敗作品、擱置）、不做 Collab 借流量；以完全獨立新帳號經營（IG＋Threads＋YouTube Shorts＋Personal Lab）。
- 原因：舊帳號定位與受眾與本 IP 不符，避免互相污染。

## ADR-008：MiniMax H3 路由照原設計（地域裁示）
- 狀態：ACCEPTED（2026-11-27 Creator 裁示）
- 決策：H3 Ref2VA 維持為對白主力路由，不因授權地域疑慮改道；裁示理由（使用地位於台灣、非美區）與灰區事實併記於專案文件。
- 原因：H3 為實測下身分保持與口型最佳的對白載體（SM-7A 實證）。

## ADR-009：Flow 預設模型改為 Omni 1.2 Flash
- 狀態：ACCEPTED（2026-11-28 Creator 指示）
- 決策：Flow 生成一律採 Omni 1.2 Flash（支援 --duration 3–15 秒），Veo 系列不再作預設；已生成的 Veo 鏡頭不重拍。
- 原因：Veo 3.1 Fast／Quality 將於 2026-12-05 退役；Omni 支援指定時長，排程彈性較佳。

## ADR-010：Seedance 只借鑑方法層
- 狀態：ACCEPTED（2026-11-28 Creator 拍板）
- 決策：借鑑其開源生態的方法層（資產鎖定表「不繼承」欄、跨鏡身分錨點、微表情圖庫＋強度分級、一維度一權威），併入分鏡規格 v2.3；Seedance 本身不列入生產存取，影片主力維持 H3。
- 原因：其 API 為全新支出線且廢片全額計費；方法層的價值與引擎綁定無關。

## ADR-011：2022 入場 Canon
- 狀態：ACCEPTED（2026-11-27 Creator 拍板）
- 決策：范蠡於 2022-11-30（ChatGPT 公開日）與「系統」同日抵達現代，已潛伏觀察近四年（會用但不肯同化：毛筆／紙本／現金）；劇本引擎加「前史痕跡」欄，2022–2026 真實舊事件可作痕跡卡（推演標 INFERENCE）；「系統為何知其名」列為季線謎團。
- 原因：使穿越抵達與 AI 時代元年同構，首集與最新時事的對撞有四年縱深可回溯。

## ADR-012：SYS-01 彈窗後製合成＋Demo 邊界條款
- 狀態：ACCEPTED（2026-11-28，規格 v2.2 AMD-05／AMD-06）
- 決策：系統彈窗一律後製四層合成（乾淨底板／彈窗幾何＋人像／方向性青光回打／音訊波形），生成 prompt 禁含全息彈窗詞彙（preflight 硬駁回）；Demo 只是同一管線的 --mode demo，僅可縮產量與精修，閘門與流程不可跳。
- 原因：DEMO-02 實證生成引擎直畫彈窗必出亂碼與表情失控；「試水降級」是 DEMO-02 失敗的結構性主因之一。
